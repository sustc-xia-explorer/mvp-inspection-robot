# omni / diff ROS1 移植验证（2026-10-26）

此文保留初始移植结果；2026-10-27 的默认参数和平滑修正见 [SMOOTH_CORRIDOR_CN.md](SMOOTH_CORRIDOR_CN.md)。

本次验证对象是本包 `core/` 和 `src/neupan_node.cpp`，外层已归档的差速 `libneupan/` 没有修改。结果表明：配置可以切换两种模型；omni 的优化与原 Python 一致，ROS1 横向输出、反馈、断流停车和现有 RViz 场景闭环均已通过功能验证。

## 环境与实现范围

- 验证主机为 Ubuntu 22.04 / GCC 11.4；使用独立的 ROS1 `ros_comm 1.15.14`、tf2 0.7.5 和 ROS1 消息，未混用系统 ROS2 消息。
- 核心依赖为 OSQP 1.x、OsqpEigen 0.11.2、yaml-cpp。默认 Eigen 3.4；另外在临时前缀中安装 Eigen 3.3.7，并重新编译对应的 OsqpEigen，完整重跑核心测试。
- 没有把当前主机的 ROS1 测试环境当作工控机 Ubuntu 20.04 / GCC 9 的实测结果。工控机应按 README 重新编译、复测。
- 运行时是 C++ Eigen / OSQP，Python NeuPAN 仅用于生成离线数值参考。

移植覆盖原 Python 的 `linear_omni_model`、`InitialPath.omni_model`、omni 位置跟踪代价，以及 `[v,phi]` 转换为世界坐标 `[vx,vy]` 的最终输出。ROS 接口增加世界到车体坐标变换、横向速度反馈、横向运动判定和诊断字段。

原 Python 的 omni 不优化车身 yaw，故本次也没有增加自主旋转或终点朝向跟踪。保留差速版已有的首步执行历史约束、正常制动变化率限制、碰撞急停和消息断流停车；这些部署保护是既有 C++ 版本的扩展，不应称为与原 Python 在所有运行条件下逐位相同。

## 原 Python 数值对照

参考文件：[omni_python_reference.json](test/data/omni_python_reference.json)。生成脚本调用原 Python `robot` 类的动力学、目标函数和约束方法，而非另写一套 Python 公式。参考版本为 `hanruihua/NeuPAN@d225c3862654ade30ccd19455997f615a689a670`，文件 SHA256 保存在参考文件中。

五组 QP 包括不同车身朝向、正反速度、正负行进角，以及障碍软约束；故意让目标 yaw 与当前 yaw 不同，检验 omni 是否正确忽略朝向代价。测试重复使用同一个 OSQP 对象，覆盖方向变化时的稀疏矩阵更新。

| 检查 | 实测最大差异 | 验收门限 |
| --- | ---: | ---: |
| 完整控制序列与 Python QP | 4.50×10⁻⁷ | 2×10⁻⁴ |
| 原目标函数值 | 1.23×10⁻⁸ | 2×10⁻⁵ |
| A/B/C 线性化矩阵 | 通过逐元素检查 | 矩阵范数差 <10⁻⁷ |
| 预测中的车身 yaw | 恒定 | <10⁻⁸ rad |

同一 QP 对照不启用部署额外的首步历史约束；启用它之后的执行行为由闭环和变化率测试另行覆盖。

## 核心回归测试

`ctest` 的 5 组测试全部通过：DUNE、NRMP、原始 diff 回放、命令限制、omni。Eigen 3.3.7 下也是 5/5 通过。omni 测试还覆盖：

- 车身 yaw=90° 时，世界 +X 对应车体 -Y；反变换可恢复原速度。
- 有符号速度反向、±π 附近的等价方向选择、零速时保留上一方向。
- 配置选择、错误模型拒绝、三种目标的闭环到达、正常控制变化率。
- 障碍进入车体时立即输出零速度。

Python 独立测试为 17/17 通过，包含旧几何和命令保护回归，以及新增虚拟底盘模型测试。

## 真实 ROS1 消息和完整仿真

测试使用独立 master，运行实际编译的 `neupan_node`，发布虚拟 TF、LaserScan、Path、TwistStamped。先验证三种模型接口，再运行实际的 `sim_complete.launch`（关闭 RViz 窗口，保留相同世界、A* 和规划节点）。

| 场景 | 结果 |
| --- | --- |
| omni 横移 | 到达；非零 `linear.y`，`angular.z=0` |
| 车身初始朝向 90° 的 omni 移动 | 到达；世界速度正确转换到车体坐标，`angular.z=0` |
| diff 直行回归 | 到达；`linear.y=0` |
| 三种接口的激光断流 | 每种均零速停车 |
| 三种接口的 TF 断流 | 每种均零速停车 |
| ROS1 `sim_complete.launch` 的 omni 走廊 | 到达、零碰撞、yaw 不变 |

完整走廊的实际消息闭环结果：

- 目标 `[4.4,-0.5]`；到达事件的误差 **0.01292 m**。
- 从世界节点启动到到达约 **79.62 s**，其中自动目标等待约 2 s。
- 最小真实矩形车体净距 **0.09030 m**；碰撞次数 **0**。
- 车身 yaw **0 rad**，未随路径转向。
- 正常速度变化率最大 **0.30000 m/s²**，行进方向变化率最大 **3.00000 rad/s**。

记录：[ROS1 总摘要](test/results/ros1_final/summary.json)、[走廊摘要](test/results/ros1_final/rviz_corridor/summary.json)、[逐帧 CSV](test/results/ros1_final/rviz_corridor/trajectory.csv)。其中净距是独立几何计算的车体到障碍距离，不是 DUNE 输出；优化的 `d_min` 使用软约束，不能作为绝不会被突破的硬停车距离。

## 结论的适用范围

以上是固定配置、固定地图和单次确定性用例的功能验证，可证明模型切换与本次移植链路工作正常，不能作为真实工况的统计通过率或实车安全保证。已验证模型语义和 ROS1 仿真，不包括执行器迟滞、轮胎侧滑、机械转角极限、CAN 档位 7 的协议映射。

现有 `fw_mini_bridge.py` 仍为 diff 档案接口，不会接受 omni 配置。实车横移桥接属于下一项工作；本次没有改变厂商驱动，也没有向底盘发出命令。
