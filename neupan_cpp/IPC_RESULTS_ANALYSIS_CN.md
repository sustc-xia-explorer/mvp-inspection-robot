## 仍存在的问题

直角场景最后停在约 `(1.13646, 1.0)`，目标是 `(1,1)`。脚本总误差容许值 0.15 m 不会让算法自动认为到达；规划配置自己的到达门限是 0.10 m，最终 0.136 m 未进入该门限。此前相同配置的 Python 版本也出现相同停点，提示需要检查共有的路径/控制收敛问题，不能直接归咎于 ROS1 移植。仍需固定输入回放才能定位数值实现差异。

三个通过场景中，原始指令最大纵向加速度约 1.5 m/s²，高于配置 `max_acce[0]=0.3`；直角最大角加速度约 2.77 rad/s²，高于 `max_acce[1]=0.6`。源码的加速度约束施加在预测序列相邻控制之间，没有把上周期实际执行指令作为首拍边界。现有 PASS 没有把该项作为门限，不代表实车指令已满足加速度限制。

工控机无障碍 core 完整 forward 均值约 0.266–0.300 ms，p95 约 0.287–0.482 ms。可以说明这些无障碍实例很快；缺少同一台 i5、同参数、同障碍输入下的 Python 串行对照，尚不能给出轻量化加速倍数或有障碍实时性结论。ROS 日志中的数十秒是带定时器的闭环墙钟时长，不能拿来除以 core 按数学时间快速执行的时长。
